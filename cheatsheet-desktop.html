🖥️ Claude Desktop 치트시트 — Code 탭 실무자용 (CLI 미포함)

다운로드부터 권한 모드·워크스페이스·Computer Use·엔터프라이즈 관리까지, 공식 문서 기준 정리
공식 문서 웹 조사 기준 최종 확인: 2026-08-12
출력 권장: A3 가로, 여백 최소, 배경 그래픽 인쇄 켜기

🟣 다운로드 & 시작

  • macOS: 유니버설 dmg (Intel/Apple Silicon)
  • Windows: x64 설치 / ARM64는 별도 설치파일
  • Linux(베타): apt 또는 .deb
  • 설치 후 로그인 → Code 탭 클릭
⚠️ Windows는 Git for Windows 필요 (설치 후 앱 재시작)

🟣 세 가지 탭

Chat일반 대화
CoworkDispatch·장기 에이전틱 작업
Code소프트웨어 개발 (이 치트시트 범위)

🟣 세션 시작 설정 (4가지)

EnvironmentLocal/Cloud/SSH/WSL(Win) 선택
Project folder작업할 폴더·저장소 선택
Model전송 버튼 옆 드롭다운(세션 중 변경 가능)
Permission mode모드 선택기(세션 중 변경 가능)

🔐 권한 모드

Manual (default)편집·명령 전 항상 확인
Accept edits파일편집+기본 명령 자동승인
Plan탐색만, 편집 전 계획 제시
Auto백그라운드 안전검사로 대부분 자동
Bypass permissions프롬프트 없음, 격리 환경 전용
⚠️ Bypass: Pro/Max는 설정→Claude Code 토글, Team/Enterprise는 조직 정책. dontAsk 모드는 CLI 전용

🖊 프롬프트 박스

  • Enter 전송, 진행 중 정정 메시지 입력 시 중단 없이 다음 단계에 반영
  • 정지 버튼: 즉시 중단
  • @파일명: 컨텍스트 추가 (로컬·SSH만, 클라우드·WSL 불가)
  • 첨부: 이미지·PDF 드래그앤드롭
  • + 버튼: 파일첨부/스킬/커넥터/플러그인

⌨ 슬래시 명령어

/ 입력 또는 +→Slash commands 로 탐색 (내장 명령어 + 커스텀·프로젝트·플러그인 스킬)
/clear, /compact, /context새 대화 시작/요약/컨텍스트 확인
/rewind, /diff체크포인트 롤백 / diff 뷰어
/model, /effort, /plan모델·추론강도 변경 / 계획 모드
/rename, /branch, /export이름변경/대화분기/내보내기
/code-review, /security-reviewdiff 검토 / 보안 취약점 검사
/background, /tasks, /fork백그라운드 분리/작업목록/복사
/loop, /goal, /recap, /insights반복실행/목표설정/요약/분석
/btw사이드 채팅 열기
/desktop(터미널에서) 세션을 데스크톱으로 이동
/ide, /mcp, /doctor, /usageIDE·MCP 관리/진단/사용량
⚠️ /permissions 등 터미널 전용 대화형 명령어는 "isn't available in this environment" 응답. /config 는 인자 무시하고 설정 화면만 열림

🖥 앱 미리보기 (Browser pane)

  • 수정 후 자동으로 dev 서버 실행·검증(스크린샷/DOM검사/클릭/폼입력)
  • 서버 드롭다운에서 시작/중지
  • Persist sessions: 재시작해도 쿠키·로컬스토리지 유지
  • HTML/PDF/이미지/영상 경로 클릭 시 Browser pane에서 열림

🌐 외부 사이트 브라우징

  • Cmd/Ctrl+Shift+B 로 Browser pane 열기
  • 첫 접근 시 승인 카드(Allow once/Always allow/Deny), 서브도메인별 개별 승인
  • 로그인 상태 공유 필요하면 Claude in Chrome 확장 사용 (Browser pane은 별도 프로필)
  • 조직 차원 allow/blocklist 및 외부 탐색 자체 차단 가능

📝 Diff 리뷰 & 코드 리뷰

  • 변경 후 +12 -1 형태 diff stats 클릭 → diff 뷰어
  • 줄 클릭해 댓글, Cmd/Ctrl+Enter 로 한번에 제출
  • Review code 버튼: 컴파일오류·명백한 버그·보안취약점 위주(스타일은 안 봄)

🔀 PR 모니터링

  • PR 생성 후 세션에 CI 상태 바 표시 (GitHub CLI gh 필요)
  • Auto-fix: 실패한 체크 자동 수정 시도
  • Auto-merge: 모든 체크 통과 시 squash 병합(GitHub에서 auto-merge 먼저 활성화 필요)
  • 완료 시 데스크톱 알림

🧩 워크스페이스 배치

패널: chat·diff·browser·terminal·file·plan·tasks·subagent (+macOS는 iOS 시뮬레이터)
  • 헤더 드래그로 위치 변경, 가장자리 드래그로 크기 조절
  • Views 메뉴에서 패널 추가
  • Cmd/Ctrl+\ 포커스된 패널 닫기

💻 터미널 & 파일 편집기

  • 통합 터미널 Ctrl+`: 세션과 동일한 작업 디렉토리·환경 공유 (로컬 세션 전용)
  • 파일 클릭 → 파일 패널에서 바로 편집·저장
  • 파일 우클릭: 컨텍스트로 첨부/다른 앱에서 열기/탐색기 표시/경로 복사

👁 뷰 모드

Normal도구 호출 요약 + 전체 텍스트 응답
Verbose모든 도구 호출·중간 단계 표시
Summary최종 응답과 변경사항만
Ctrl+O 로 순환 전환

📊 사용량 확인

모델 선택기 옆 사용량 링 클릭 → 컨텍스트 사용량(세션별) + 플랜 사용량(전체 서피스 공유)

🖱 Computer Use

  • 화면·앱 직접 조작 (CLI 없는 GUI 자동화용)
  • macOS·Windows Pro/Max 리서치 프리뷰, Team/Enterprise 불가
  • 기본 꺼짐: 설정→General→Computer use 토글, macOS는 손쉬운 사용+화면 기록 권한 추가 필요
  • View only(브라우저 등) / Click only(터미널·IDE) / Full control(그 외) 3단계
  • 세션당 1회 승인 (Dispatch 세션은 30분마다 재승인)
⚠️ 실제 데스크톱을 조작 — 샌드박스 Bash와는 다른 신뢰 경계

🗂 세션 관리

  • Cmd/Ctrl+N 새 세션, 여러 세션 병렬 실행
  • Git 저장소는 세션마다 자동 Git worktree로 격리(.claude/worktrees/)
  • Cmd/Ctrl 누르고 사이드바 클릭 → 2개 세션 분할 보기
  • 완료 후 보관 아이콘, PR 병합 시 자동 보관(Auto-archive) 설정 가능

💬 사이드 채팅

Cmd/Ctrl+; 또는 /btw 로 열기 — 메인 세션 컨텍스트는 읽지만 기록엔 안 남음, 앱 종료 시 사라짐 (로컬·SSH·WSL만)

📋 백그라운드 작업 & 세션 간 작업

  • Tasks 패널: 서브에이전트·백그라운드 셸·동적 워크플로우 진행상황
  • "다른 세션이 뭐 했어?" 같은 자연어로 다른 Code 세션 확인·메시지·이름변경·보관 요청
  • 최근 20개 세션까지, 클라우드 세션은 제외

☁ 클라우드 세션 & 이어가기

  • Environment에서 Cloud 선택 → 앱 종료해도 계속 실행, claude.ai/code·모바일 앱에서 확인
  • 여러 저장소 동시 추가 가능
  • Continue in 메뉴: 웹 세션으로 전송 또는 IDE로 열기

📱 Dispatch (Cowork 탭)

  • 휴대폰에서 작업 지시 → 개발 작업이면 자동으로 Code 세션 생성 (Dispatch 배지 표시)
  • 완료·승인 필요 시 폰으로 푸시 알림
  • Pro/Max 전용, Team/Enterprise 불가

🔌 커넥터 연결

+ 버튼 → Connectors: Google Calendar/Slack/GitHub/Linear/Notion 등 (로컬·SSH만, 클라우드·WSL 불가)
설정→Connectors 에서 관리·연결 해제

🧰 스킬 & 플러그인

  • / 입력 또는 +→Slash commands 로 내장 명령어·커스텀 스킬·플러그인 스킬 탐색
  • +→Plugins: 설치된 플러그인 확인, "Add plugin"으로 마켓플레이스 설치
  • 플러그인은 클라우드·WSL 세션에서는 사용 불가

⚙ 프리뷰 서버 설정 (.claude/launch.json)

name / runtimeExecutable식별자 / 실행 명령
runtimeArgs / args명령 인자
port (기본 3000)서버 포트
cwd / env작업 디렉토리 / 환경변수
autoPort포트 충돌 시 자동 재할당 여부
program / urlnode 스크립트 직접 실행 / 접속 주소
autoVerify: 기본 켜짐(수정마다 자동 검증), false로 끌 수 있음

🖧 환경 종류

Local내 컴퓨터에서 직접 실행
CloudAnthropic 관리 인프라, 앱 꺼도 계속 실행
SSH원격 머신 연결 (Linux·macOS만)
WSL (Windows)WSL2 배포판 안에서 실행

🏢 엔터프라이즈 관리

  • 관리 콘솔: Code 데스크톱 사용 여부, 웹 세션, Remote Control, Bypass 모드 비활성화 등 제어
  • Managed settings: disableAutoMode, sshHostAllowlist, managedMcpServers 등
  • macOS는 MDM(Jamf/Kandji), Windows는 그룹 정책/레지스트리로 배포·정책 관리

🔒 네트워크 & 데이터 처리

주요 허용 도메인: anthropic.com, claude.ai, claude.com, claude.app, *.claudeusercontent.com (HTTPS 443)
로컬 세션은 로컬 처리, 클라우드 세션은 Anthropic 관리 인프라에서 코드·대화 컨텍스트 처리

📊 CLI → 데스크톱 대응표

--model sonnet모델 드롭다운
--resume, --continue사이드바에서 세션 클릭
--permission-mode모드 선택기
--dangerously-skip-permissionsBypass permissions 모드
--add-dir클라우드 세션의 + 버튼(저장소 추가)
--allowedTools/--disallowedTools세션별 대응 없음(설정파일 규칙은 적용)
--verboseVerbose 뷰 모드
--print, --output-format미지원 (대화형 전용)
MAX_THINKING_TOKENS로컬 환경변수 에디터

📋 기능 비교: CLI vs 데스크톱

권한 모드CLI는 dontAsk 포함 전체 / 데스크톱은 4종+Bypass
서드파티 프로바이더CLI는 Bedrock 등 / 데스크톱은 기본 Anthropic API
MCP 서버CLI는 설정파일 / 데스크톱은 Connectors UI 또는 설정파일
플러그인CLI는 /plugin / 데스크톱은 플러그인 관리자 UI
파일 첨부CLI 불가 / 데스크톱은 이미지·PDF 지원
세션 격리CLI는 --worktree / 데스크톱은 자동 worktree
반복 작업CLI는 cron/CI / 데스크톱은 Scheduled tasks
Computer UseCLI는 macOS /mcp 활성화 / 데스크톱은 앱 내장
iOS 시뮬레이터CLI는 Computer Use로 구동 / 데스크톱은 전용 패널
DispatchCLI 없음 / 데스크톱은 사이드바 지원
스크립팅/자동화CLI는 --print·Agent SDK / 데스크톱 미지원

🔗 CLI와 공유되는 설정

  • CLAUDE.md, CLAUDE.local.md — 둘 다 사용
  • MCP 서버(~/.claude.json, .mcp.json) — 공유
  • Hooks, Skills — 공유
  • ~/.claude/settings.json — 공유(권한 규칙 등)
  • 터미널에서 /desktop 입력 → 현재 세션을 데스크톱 앱으로 이동

💡 데스크톱 vs CLI, 언제 무엇을

병렬 세션 관리, 패널 배치, 변경사항 시각적 검토 → 데스크톱
스크립팅, 자동화, 터미널 워크플로우 선호 → CLI

🛠 트러블슈팅

  • 403/인증 오류 → 로그아웃 후 재로그인, 유료 구독 확인
  • 화면 멈춤/빈 화면 → 재시작, 업데이트 확인, 방화벽 CDN 허용 확인
  • "Failed to load session" → 폴더 존재 확인, Git LFS 설치 확인
  • Windows "Git is required" → Git for Windows 설치 후 재시작
  • MCP 서버 Windows 오류 → 설정 확인, 앱 재시작, 작업관리자에서 프로세스 확인
